# 当前工具集与剩余缺口

本文反映 P0 补齐后的实现。重复读取与预算问题见 [修复复盘](agent_read_loop_fix.md)。

## 已实现

CLI 绑定 Workspace 时注册 10 个工具：

| 工具 | 能力 |
| --- | --- |
| `add` | 加法示例 |
| `list_dir` | 目录发现、递归、噪声目录过滤、条目限制 |
| `find_files` | 文件名/路径 glob、类型过滤、结果限制、遍历前剪枝 |
| `grep` | 内容正则搜索、路径/文件名过滤、行号、命中数限制 |
| `read_file` | UTF-8 读取、行号和分页，默认 200 行、文件上限 2 MiB |
| `write_file` | 创建、原子覆盖、`mode="append"` 追加 |
| `edit_file` | 唯一精确替换或 `replace_all`，保留换行和权限 |
| `apply_patch` | edits 数组形式的批量精确替换，全部校验后提交，失败尝试回滚 |
| `file_info` | 类型、大小、UTC 修改时间、行数、UTF-8/NUL 检测，大文件有界采样 |
| `run_command` | 本地 shell、cwd 校验、超时、进程组清理、输出限制、宿主确认钩子 |

Registry 已有统一异步超时、输出限制、异常转换和数值上下界校验。
文件路径经过 Workspace 校验；shell 仍拥有当前用户权限，cwd 校验不是系统沙箱。

## 下一批优先项

1. **文件移动/复制/删除**：提供明确的参数和确认/恢复语义。当前 `run_command`
   已可执行这些操作，独立工具的价值是减少 shell 依赖并细化权限。
2. **长进程会话**：启动开发服务后继续工作，支持获取后续输出和主动停止。
   当前 `run_command` 仅面向有限时间的前台命令，结束时会清理进程组。

## 配套基础设施

- 参数校验已有嵌套 object、array items、数值上下界和数组长度限制。
- 独立只读调用可并发，写操作仍应保持顺序与依赖关系。
- 记录工具参数摘要、耗时、输出大小和失败原因，便于定位循环与慢调用。
- 危险命令检测是常见写法匹配，不能替代宿主隔离和按工具划分的权限策略。
- 显式任务清单可改善长任务进度展示，但不替代正确的上下文与执行循环。

## 按需能力

- `web_fetch` / `web_search`：获取外部文档和变化中的事实。
- PDF、表格、图片读取：独立处理格式，不改变 `read_file` 的文本职责。
- 专用 Git 操作和环境信息：已有命令工具可以完成，是否拆成独立工具取决于
  权限、稳定输出格式与交互成本需求。

目前已经具备读代码、编辑、执行测试的基本闭环。继续增加工具前，应优先保证
模型能力配置生效、充足空间下保留源码、预算压力下能回收本地摘要，以及避免
同一文件被不同工具反复阅读。
